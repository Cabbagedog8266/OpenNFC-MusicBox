# OpenNFC Music Box

**A battery-free NFC music box** · STM32G031 + NTAG I²C plus

[简体中文](README.md) | **English**

Hold a phone near the on-board NFC antenna, and the board harvests power from the RF field. An STM32G031 drives a passive buzzer through PWM to play a melody, while an on-board NTAG I²C plus provides an NDEF area the phone can read and write. No battery is required.

> This repository is a complete reference design: PCB antenna, Gerber, EasyEDA project, KiCad coil footprint, STM32 firmware and a melody-extraction workflow.
>
> Styled Chinese documentation: [GitHub Pages](https://cabbagedog8266.github.io/OpenNFC-MusicBox/)

## Features

- **Battery-free** — powered entirely by the phone's NFC field
- **Undervoltage protection** — PVD stops playback and enters STOP mode when the field sags, then resumes automatically
- **Differential PWM** — TIM1 CH1/CH1N drives a passive buzzer with dynamic frequency and 50% duty cycle
- **Phone-writable tag** — NTAG I²C plus (1K, I²C address `0x55`) provides NDEF storage
- **No tag lockout** — every boot rewrites the CC, an empty NDEF TLV and clears the I²C lock
- **Replaceable antenna** — the `R0` footprint is reserved for your own coil
- **Replaceable melody** — the score is a `{frequency, duration}` array compiled into the firmware

### Antenna notes

- The `R0` footprint is a placeholder; replace its footprint with your own antenna. The resulting **DRC warnings are expected and can be ignored**.
- Coils generated by Pro Antenna Designer use through-hole pads by default and also produce harmless DRC warnings.
- Keep **Q ≈ 20 and never above 20** for sufficient bandwidth and power transfer.
- Keep a **5 mm** clearance around the coil (both sides) free of pads, traces and other metal.
- A small resonance offset costs about 0.05 dB. Without lab equipment, use the LC matching values from the designer.

> **Required after fabrication**: the inner terminal of the KiCad footprint (Pad 2) is a plated through-hole and must be **routed out on B.Cu**. It is not part of the Gerber artwork and no board house will do it for you. Without that trace the coil is an open circuit. See [`hardware/kicad-coil/README.md`](hardware/kicad-coil/README.md).

## Firmware

### Requirements

- CMake ≥ 3.22 and Ninja
- `arm-none-eabi-gcc` (Arm GNU Toolchain)
- STM32CubeProgrammer + ST-Link for flashing
- Optional: STM32CubeMX to edit the peripheral configuration

### Build and flash

```bash
cd firmware
cmake --preset Release
cmake --build --preset Release
```

The output is `firmware/build/Release/project.elf`. Flash it with ST-Link:

```bash
STM32_Programmer_CLI -c port=SWD -w firmware/build/Release/project.elf -v -rst
```

You can also open the ELF in the STM32CubeProgrammer GUI. `firmware/project.ioc` opens in STM32CubeMX for regeneration; custom logic lives inside `USER CODE` blocks, so verify it survived regeneration.

### Changing the song

The score is in [`firmware/Core/Src/music_data.c`](firmware/Core/Src/music_data.c). Each entry is:

```c
{frequency_hz, duration_ms}
```

A frequency of `0` is a rest. After editing the array, update `MUSIC_LEN` in [`firmware/Core/Inc/music_data.h`](firmware/Core/Inc/music_data.h) to match the actual length, then rebuild and flash.

### Key files

| File | Purpose |
| --- | --- |
| `Core/Src/main.c` | Clock, initialization, main loop, PVD handling |
| `Core/Src/buzzer_driver.c` | PWM frequency control, playback state machine, undervoltage pause/resume |
| `Core/Src/music_data.c` | Melody array (default demo song) |
| `Core/Src/i2c.c` | NTAG I²C init, CC/NDEF writes, I²C unlock |
| `Core/Src/tim.c` | TIM1 PWM configuration |

## NTAG read/write

Use the official **NXP TagWriter** app ([Google Play](https://play.google.com/store/apps/details?id=com.nxp.nfc.tagwriter)).

> **The first time you write the dataset, erase the tag and format it as NDEF before writing the data.**

On every boot the firmware initializes the tag over I²C so the phone side stays writable:

1. Write the CC: Block 0 `byte[12..15] = E1 10 6D 00`
2. Write an empty NDEF TLV: Block 1 `byte[0..3] = 03 00 FE 00`
3. Write configuration Block `0x3A` (NFC writable, 20 ms WDT, configuration not locked)
4. Clear `NS_REG.I2C_LOCKED` (register `0xFE`, bit 6)

If the phone reports the tag as read-only or refuses to write: power-cycle the board and try again; if it still fails, use TagWriter's "Erase tag / Format as NDEF" and retry.

> **Never change** `byte[0]` of Block 0. It must stay `0xAA` to keep the I²C address at `0x55`. Writing `0x04` changes the slave address to `0x02` and I²C communication is lost.

## Audio conversion

Pick the workflow that matches your material:

| Situation | Workflow |
| --- | --- |
| You already have a score | Edit [`music_data.c`](firmware/Core/Src/music_data.c) and update `MUSIC_LEN` |
| You have a monophonic MIDI but no melody TXT | Use [prts.online](http://prts.online/) and choose "keep highest note" |
| You only have a song | Use [MelodyExtractor](https://github.com/Cabbagedog8266/melody-extractor) to extract the melody, then clean it up |

The extractor writes a TXT where each group is `{frequency, duration}` in Hz and ms, five groups per line. Convert it into a C array:

```c
const MusicNote_t music_score[MUSIC_LEN] = {
    {1396, 238}, {0, 25}, {932, 475}, {0, 52}, {1864, 476},
    /* ... */
};
```

The `MelodyExtractor_Setup_v1.0.0.exe` installer is attached to this repository's [Releases](https://github.com/Cabbagedog8266/OpenNFC-MusicBox/releases).

## FAQ

**No sound after flashing?**
- Make sure the buzzer is **passive** (an active buzzer only produces a fixed tone).
- Align the phone's NFC antenna with the center of the on-board coil; phones vary a lot.
- Check the TIM1 divider: `Prescaler = 15` in `tim.c` matches `BUZZER_PWM_CLK = 1 MHz` in the driver. They must stay consistent.

**High notes missing or out of tune?**
- Increase the TIM1 clock or decrease the prescaler, and update `BUZZER_PWM_CLK` in `buzzer_driver.c` accordingly.

**Playback stops midway?**
- Usually the NFC field is too weak and PVD trips. Hold the phone closer, move metal away, or reduce the load. The firmware resumes automatically when the voltage recovers.

**The phone cannot write to the tag?**
- Erase and format the tag as NDEF first, then power-cycle the board to clear the I²C lock.

**Should I care about the DRC warnings?**
- Antenna-related warnings are expected. Other electrical rule violations should still be reviewed.
